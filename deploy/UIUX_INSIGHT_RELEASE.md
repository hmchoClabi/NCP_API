# UI/UX 감사 반영 및 금일 Cloud Insight 집계

## 변경 범위와 보존 계약

- 기존 저장 스냅샷을 읽어 통합 대시보드에 고객명, 계정, 인스턴스, 알람·조건, 발생 횟수, 최초·최근 시각, 수집 당시 종료 여부, 보고서 링크를 표시한다.
- 한국시간 **오늘 성공·부분 수집으로 완료된 보고서**가 대상이다. 일일·주간·월간 등 해당 보고서 조회기간에 발생한 이벤트이므로 오늘 발생한 알람이나 실시간 모니터링과는 다르다. 실패·대기 작업은 생성 이력에서 확인한다.
- 고객/계정/환경/제품/인스턴스/규칙/지표/임계값/측정 조건/차원별로 묶는다. 서로 다른 이벤트 ID만 발생 횟수에 더하고 여러 보고서에 반복 저장된 같은 이벤트는 한 번만 센다. 가장 최근 보고서의 이벤트 상태를 우선한다.
- 이벤트 ID가 없으면 동일 대상·조건·발생시각을 중복 판별에 사용한다. 발생시각도 없으면 정확한 중복 제거가 불가능하다는 안내와 함께 표시한다. 수집 실패·부분 수집·비활성·구형 상태 미확인은 정상/알람 없음으로 단정하지 않는다.
- MSP 민간/공공 접근 범위, 고객 권한, CSRF, 보고서 파일 경로 검증·체크섬·CSP를 유지한다.
- DB 스키마, 수집 API, 보고서 데이터, 일정, Worker 실행, 고객/사용자 관리의 저장 계약은 변경하지 않는다. 신규 의존성도 없다.
- 과거 보고서 HTML은 **재작성하지 않는다**. 상세 화면의 iframe에만 표시 스타일을 적용한다. 새로 생성하는 보고서는 동일한 스타일을 파일에도 포함한다.
