# 결정 기록 (Decision Log)

> 사용자가 내린 정책·설계 결정을 기록합니다. 지시서·코드가 이 문서와 충돌하면 **이 문서가 우선**합니다.
> 새 결정이 생기면 번호를 이어 추가하고, 이미 기록된 결정을 바꿀 때는 지우지 말고 "대체됨"으로 표시한 뒤 새 항목을 씁니다.

---

## D1. 수집은 최대한, 범주 선택은 "표시"에만 적용 (2026-10-07)

**결정**: NCP 자원·지표·이벤트는 향후 기능 확장을 위해 **가능한 범위를 최대한 수집·저장**합니다.
고객별 출력 설정의 자원 범주·모니터링 범주 선택은 **보고서에 무엇을 보여줄지**를 정할 뿐, 수집 범위를 줄이지 않습니다.

**배경**: `app/runner.py:2321`에서 선택 범주로 걸러낸 `infrastructure_data`가 쓰이지 않는 것은 이 설계에 따른 것입니다.
화면 표시는 `ReportResult.display_infrastructure`(`app/report_models.py:100`)와 렌더러에서 범주를 다시 적용합니다.

**적용 규칙**
- 수집 단계에서 범주 선택으로 API 호출을 생략하는 변경을 하지 않습니다(성능 개선 목적이라도 데이터 손실이 생기면 금지).
- 저장 용량 절감은 **중복 제거와 표현 압축**으로만 합니다. 수집한 데이터 자체(시각·값·차원)를 버리지 않습니다.
- `build_collection_plan`(`app/report_pipeline.py:94`) 등 현재 코드에서 선택 범주가 수집 대상을 줄이는 곳이 있으면 **고치지 말고 보고**합니다(이 원칙과의 차이를 사용자가 판단).
- 미사용 변수 `infrastructure_data`는 별도 소규모 커밋에서 삭제할 수 있으며, 그 자리에 이 원칙을 설명하는 주석(`D1 참조`)을 남깁니다.
- UI에서 범주 선택 영역의 이름은 "수집 범위"가 아니라 **"표시 범위"**로 씁니다.

## D2. 리포트 단건 삭제: MSP 운영자 허용 유지 + 최신 정상본 보호 (2026-10-07)

**결정**: MSP 운영자(`MSP_OPERATOR`)도 범위 내 리포트를 1건씩 삭제할 수 있도록 **현행 권한을 유지**합니다.
단, 단건 삭제에도 일괄 정리와 같은 **최신 정상본 보호**를 켭니다.

**적용 규칙**
- `POST /reports/<report_id>/delete`(`webapp/portal_routes.py:172`)의 삭제 실행 시 `protect_latest`를 기본 **true**로 합니다.
  계정·보고서 유형별 최신 정상 리포트는 단건 삭제로 지울 수 없고, 화면에 "최신 정상 리포트라 삭제할 수 없습니다" 안내를 보여줍니다.
- 권한 집합(MSP_ADMIN, MSP_OPERATOR, SYSTEM_ADMIN + 범위)은 바꾸지 않습니다. 일괄 정리는 계속 관리자 전용입니다.
- 회귀 테스트: 운영자 단건 삭제 성공(최신 아님), 운영자·관리자 모두 최신 정상본 삭제 거부.

## D3. CPU·메모리·디스크 임계치 하한 완화, 기본값 유지 (2026-10-07)

**결정**: 고객별로 더 이른 경고를 설정할 수 있도록 입력 범위를 **50–100%**로 넓힙니다. 기본값(주의 90%, 위험 95%, 지속 15분)은 그대로입니다.

**적용 규칙**
- `app/report_options.py:8–69`의 CPU·메모리·디스크 warning/critical 6개 필드 하한을 90 → **50**으로, 상한 100 유지.
- 서버 검증에 **warning < critical** 조건을 추가합니다(같거나 역전되면 저장 거부 + 한국어 오류).
- 템플릿의 `min`/`max` 하드코딩을 없애고 `report_options.py`의 상수에서 값을 받아 출력합니다(범위 정의 단일화).
- 기본값과 기존 고객 설정은 바뀌지 않으므로 기존 판정 결과도 바뀌지 않아야 합니다(회귀 테스트로 증명).
- 70% 미만 입력 시에는 저장은 허용하되 "경고가 자주 발생할 수 있습니다" 안내를 보여줍니다.
