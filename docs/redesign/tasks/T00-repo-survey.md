## 조사 항목

1. **스택** — 언어·웹 프레임워크·템플릿 엔진·ORM·DB 종류·마이그레이션 도구·테스트 프레임워크·린터.
2. **실행 구조** — 웹 프로세스, 백그라운드 작업 실행 방식(스케줄러가 무엇인가: APScheduler / Celery / RQ / k8s CronJob / 자체 루프 등),
   작업 큐, 동시성 제한, 재시도 로직 유무. 이력에 보이는 `Scheduler` 요청자가 어디서 오는지.
3. **라우트 표** — 메서드·경로·핸들러 함수·템플릿·권한(MSP 관리자/운영자/고객 사용자). 00-context.md 1절 표의 모든 화면 + 모든 POST 엔드포인트.
4. **데이터 모델** — 고객(tenant)·계정(account)·API 키·사용자·일정(schedule)·작업(report job)·보고서(report)·보존 정책·
   출력 설정·알림(notification) 테이블과 관계. 필드 목록과 인덱스.
5. **수집 파이프라인** — 어떤 NCP API를 어떤 순서로 호출하는지, 결과를 어디에 어떤 형식으로 저장하는지
   ("관련 수집 데이터"의 실체), 실패·부분 수집 판정 방식.
6. **분석** — `analysis_enabled`(결정론적 운영 분석)의 구현 위치, 입력과 출력, 임계치 사용 방식.
7. **렌더링** — 보고서 HTML을 만드는 코드와 템플릿 위치, 인라인 CSS/JS 출처, 렌더 중 `now()`·난수·비정렬 순회 사용 여부(재현성 저해 요소 목록).
8. **저장소 레이아웃** — PVC 경로 구조, 보고서 산출물·수집 데이터 파일명 규칙, 정리(data-cleanup) 작업이 지우는 대상.
9. **Insight 알람** — 대시보드 "금일 수집 Cloud Insight 알람" 패널의 데이터 출처와 중복 제거 코드 위치, 사용하는 NCP API.
10. **알림** — `/notifications` 엔드포인트, 이벤트 생성 지점, 저장 여부.
11. **프런트엔드 자산** — CSS 5개·JS 파일의 로드 위치(base 템플릿), 각 규칙이 어떤 템플릿에서 쓰이는지 대략 매핑. 사용되지 않는 셀렉터 후보.
12. **빌드·배포** — `build-46 · d222302` 표기가 만들어지는 곳, Dockerfile/Helm/k8s 매니페스트, 환경 변수 목록(값 제외).
13. **테스트 현황** — 테스트 수, 커버되는 영역, 실행 명령.
14. **관리 명령(CLI) 진입점** — 이후 지시서의 `<cli>` 자리에 들어갈 명령(예: `python -m app`, `flask`, `manage.py`)과 새 하위 명령을 추가하는 방법.
15. **보고서 유형 값** — 즉시 생성 폼 hidden `report_type`의 실제 값, 일정·작업·보고서 테이블의 유형 컬럼 값 → `00-context.md` 11절 열거형과의 매핑.
16. **Cloud Insight API 능력** — 이벤트 응답에 종료 시각/상태가 있는지, 현재 발생 중 알람 목록 API가 있는지, 지표 단위 필드, 호출 한도(T09 0절).
17. **기존 쿼리 파라미터 이름** — `/history`의 고객 필터 파라미터명, `/msp/users?tenant_id=` 처리 여부, 기타 목록 파라미터.
18. **정리 상태 값** — 데이터 정리 화면 "정리 상태" 열의 코드 값 전부.
19. **과거 산출물의 정적 자산 참조** — PVC에 저장된 기존 보고서 HTML에서 `/static/` 참조가 있는지 grep 결과(T01에서 CSS 파일을 지워도 되는지 판단).
